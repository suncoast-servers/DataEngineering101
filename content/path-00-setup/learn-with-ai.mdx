## Why

Many working data engineers use AI daily. The skill is not "prompt and paste"—it is **faster iteration with verification**.

## Concept

**Do**

- Ask AI to explain errors and tradeoffs.
- Generate **tests** and **boilerplate**, then edit.
- Request refactors you can review in a diff.

**Do not**

- Ship code you cannot explain in an interview.
- Paste production secrets or customer data into tools.
- Skip running pipelines because AI "said it works".

## Do

1. Pick a tiny script (for example `hello.py`).
2. Ask your assistant: "Add a type hint and a one-line docstring; explain why."
3. Break the script on purpose; ask for diagnosis **before** accepting a fix.

## AI prompt card

> I'm a beginner data engineer. When I use AI on SQL or Python homework, what checklist should I run before I commit? Format as a short markdown checklist.

## Exercise

Intentionally introduce a syntax error in `hello.py`, fix it with AI help, and write **in your own words** what was wrong in `notes/ai-policy.md`.

## Check

- Name two interview questions you could answer about code AI helped write.
- What should you never put in a chat window?
